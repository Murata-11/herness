# A9E-09 CSVの蓄積とAWSへの定期送信

## 仕様と根拠

- ABOSはランタイム生成データ向けの非ロールバック領域 `/var/app/volumes` を提供する。eMMCの `app` はパーティション表上2.8 GiBで、アプリ領域と共用する。[M](index.md) §2.7 表2.10 p.59、§3.3.5.1 表3.4 p.115。
- Amazon S3を送信先とする場合、Greengrass Stream ManagerのS3エクスポートは、ローカルファイルを参照するエクスポートタスクを受け取り、転送状態を取得できる。タスク受付後も、転送結果が確定するまで元ファイルを保持する。選択時は必要なコンポーネント、追加メモリ、IAM権限、スプール領域を確認する。アプリ自身がS3に送信する構成も候補で、その場合は送信・再送・状態管理をアプリが担う。[AWS Stream ManagerのS3エクスポート](https://docs.aws.amazon.com/greengrass/v2/developerguide/stream-export-configurations.html#stream-export-configurations-s3) [AWS Stream Managerの要件](https://docs.aws.amazon.com/greengrass/v2/developerguide/stream-manager-component.html)

## レビュー観点

- 同一ファイルシステム上で、一時ファイルに書く → 同期・確定名へ公開する → 送信する → AWS側の成功に対応する状態を永続化する → ローカルファイルを削除する、という順序を候補にする。起動時は未確定・確定済み未送信・送信結果不明のファイルを判別する。
- デバイスID、採取範囲、連番などから重複を判定できるオブジェクトキーを設計する。アップロードの応答を失った後の再送で重複集計や意図しない上書きが起きないことを試す。
- 最低限の滞留量は「実測CSV生成バイト/秒 × 想定最大WAN断秒数」で見積もる。ファイル確定中の分、ログ、送信中の分、更新作業領域と空き容量の余裕を別途計上する。回線復旧後の実効転送速度が生成速度を上回るか、処理能力も確認する。
- 採取周期、ローテーション条件、送信周期、遅延と欠損の許容、容量上限時の保持・停止・通知方針を定義する。CSVにはタイムゾーンまたはUTC、文字コード、スキーマ版、欠測の表現を指定する。
