# A9E-05 更新・量産・ロールバック

## 仕様と根拠

- ABOSは署名済みSWUを使って更新する。OS等はA/B構成で、更新後の起動失敗時の自動ロールバックを備える。コンテナや二面化する設定の更新もSWUで扱える。自動ロールバックの可否・状態は `abos-ctrl status` の `rollback-status` 欄で確認する。[M](index.md) §2.1.3 pp.42–44、§3.3.4 pp.108–114、§6.3 pp.365–373、§6.24 pp.555–557。
- 量産での書き込みにはインストールディスクまたはSWUの手順がある。マニュアルには作成・書き込みと書き込み後の動作確認がある。[M](index.md) §3.3.6 pp.116–117、§4.3–4.6 pp.323–340。
- ABOSの保守ポリシーと推奨更新を確認する。稼働版と添付マニュアルの版を記録し、メーカーの配布情報で対象リリースを照合する。[M](index.md) §2.1.4 p.44。[ソフトウェア配布](https://armadillo.atmark-techno.com/armadillo-iot-a9e/resources/software)

## レビュー観点

- ABOS SWUが管理するOS・コンテナと、Greengrass Deploymentが管理するコンポーネント・設定の更新責任を決める。同一設定の複数経路での上書きを防ぎ、旧OS／新コンポーネントや新OS／旧コンポーネントの組み合わせを確認する。
- 更新失敗、更新直後の再起動、手動ロールバックを試す。ABOSの起動状態と、PLC通信・CSV送信・指令処理の業務上の正常性を別々に確認する。ロールバック後も処理済み指令や未送信キューの整合性が維持されるか確認する。[A9E-03](A9E-03-persistence.md)
- 量産イメージから端末を複製するときは、環境共通のファイルと、端末単位のIoT Thing・証明書・秘密鍵・PLC設定の払い出しを分ける。
