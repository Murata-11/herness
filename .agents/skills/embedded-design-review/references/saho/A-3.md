# A-3 ソフトウェア部品は単機能になるように設計する

- 適用場面｜部品やモジュールに複数の機能が集まり、変更が波及している。
- 検索語｜単機能、高凝集、責務、モード引数、部品分割、変更の副作用
- 出典｜IPA『組込みソフトウェア向け設計ガイド［事例編］』（2012年）、誌面 pp. 24–25、PDF pp. 26–27

## 判断の根拠

対象の粒度に合った単一の目的を部品に持たせると、変更と試験の対象が明確になる。モード別の機能が独立なら、共通部分を抜き出し、機能ごとの変更を局所化する。

## 確認事項

- 部品の目的を一文で説明でき、公開操作・データがその目的に合っているか？
- 一つのモードの変更で他のモードの振る舞いが変わらないか？

## 留意点

責務を細分化すると依存関係が増えることがあるため、部品の粒度と全体の結合度も確認する。
