# C-3 状態遷移を行うモジュール間で状態の一貫性が保たれるように設計する

- 適用場面｜複数モジュールが同じシステム状態を個別に持っている。
- 検索語｜状態同期、状態不一致、共有状態、一元管理、表示と実機がずれる
- 出典｜IPA『組込みソフトウェア向け設計ガイド［事例編］』（2012年）、誌面 pp. 136–139、PDF pp. 138–141

## 判断の根拠

同じ状態を別々に更新すると、イベントの配送や処理の違いで状態がずれることがある。共通状態の管理を一つの担当に集約する方法を検討する。

## 確認事項

- システム全体で一致すべき状態と、更新を決める担当が明確か？
- イベント通知が一方に届かない場合も矛盾を防げるか？

## 留意点

一元化で状態の組み合わせが膨らむ場合は、共通状態と局所状態の分け方を見直す。

## 作図の観点

各モジュールの状態遷移とイベントの配送先を図示し、一方だけが更新される経路を確認する。
