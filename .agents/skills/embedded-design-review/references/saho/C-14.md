# C-14 機能の変更・追加のときにはソフトウェアの静的構造を崩さないように注意する

- 適用場面｜既存構造へ機能を足す際に、モジュールの分担が崩れそうになる。
- 検索語｜静的構造、機能追加、責務、アーキテクチャ、設計原則、構造維持
- 出典｜IPA『組込みソフトウェア向け設計ガイド［事例編］』（2012年）、誌面 pp. 161–163、PDF pp. 163–165

## 判断の根拠

既存構造が持つ責務と依存関係を理解し、新機能をどこへ置くか決める。元の構造と各機能の割当てを確かめると、例外的な依存の積み重なりを防ぎやすい。

## 確認事項

- 新機能は既存のどの責務に属するか？
- 追加前後で構成要素と依存の規則が保たれるか？

## 留意点

既存の構造で収まらない場合は、変更理由と影響範囲を明確にし、設計として見直す。

## 作図の観点

変更前後の静的構造図と機能の割当てを比較し、責務を越える依存が増えていないか確認する。
