# 設計相談の進め方

1. 相談を独立した論点に分け、対象と症状を表す短い検索語を選ぶ。リポジトリのルートで `python3 .agents/skills/embedded-design-review/scripts/saho.py search "同期通信" "応答が返らない"` のように実行する。相談の原文をそのままシェルに展開せず、各検索語をシェルに合った方法で引用する。初回は最大3件。候補が合わなければ同義語で引き直し、必要に応じて同じ検索に `--offset 3` を付ける。
2. 有力な1〜2件を `python3 .agents/skills/embedded-design-review/scripts/saho.py show A-10` で確認する。ID指定の相談ではここから始める。既定の節は「判断の根拠」と「確認事項」。必要に応じて `--section notes`（留意点）、`--section related`（関連作法）、`--section diagram`（作図の観点）、`--section figures`（原典の図表番号）を指定する。同じ節の再取得は省く。
3. 相談で分かる設計事実を挙げ、作法が適用できる理由と、具体的な確認・改善案を結び付ける。判断ごとに、実際に読んだ作法のID・MDへのリンク・原典の誌面ページを添える。作法から導いた提案や仮定はそのように示す。判断を左右する前提は確認事項として挙げる。根拠にできる作法が見つからないときは、その旨を伝える。

採用した作法と相談内容から、遷移漏れや処理順序など、図で検証する具体的な問いを特定できたら、自動で作図する。作法に「作図の観点」があれば `--section diagram` で取得し、[作図の手順](diagram-request.md) に進む。ユーザが作図を求めた場合もこの手順を使う。文章だけで論点を確認できる相談や、文章での回答を指定された相談はここで回答をまとめる。

端末を利用できない場合は、[作法集](saho/)に範囲を絞ってエディタの検索を使う。根拠の確認に進む候補のファイルだけを開く。
